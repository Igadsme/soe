# Fly template — owner review required

No resources are created by this repository. Run provider tooling only after owner review. Build from the repository root with `infra/fly/fly.toml`. Replace the app/region placeholders. Inject session secret, admin hash, database URL, Redis URL, CORS origin and discovery credentials using the owner's secret manager. `release_command` migrates once before release; validate private connectivity and migration serialization with your platform configuration.

This API-only template disables metrics because a platform public API would otherwise expose them. Keep disabled until private ingress or token authentication and public path blocking are implemented. It uses one Gunicorn worker; reproduce Compose's per-container metrics directory and child-exit configuration before using multiprocess metrics.

Deploy frontend separately from `infra/frontend/Dockerfile` (build-time NEXT_PUBLIC_API_URL must be the browser origin). Put an owner-managed gateway in front of both applications routing /api/*, /health and /ready to API and everything else to frontend, blocking /metrics. Same origin is required for CSRF cookies. Caddy's Compose upstream names are not platform DNS names: adapt upstreams and trusted proxy CIDRs to actual platform peers. Review provider forwarded-header behavior; do not trust every address.

Worker uses the API image with command `python -m app.worker`, the same runtime secrets, and no public HTTP service. PostgreSQL and Redis must already exist with private networking, appropriate TLS, backups and least-privilege access. No database/Redis creation commands are included. API and worker need shared media and Whisper storage: host-local volumes cannot simply be shared across machines. This requires an owner-reviewed storage adapter/topology before media processing works across hosts. Review worker heartbeat checks, resource allocation, FFmpeg limits, backup scheduling, RPO/RTO, release rollback and regional/data policies. Do not deploy this template unchanged.
